# Starcraft 2 - Remaining Exporter Issues

Last updated: 2025-12-22

## Summary
The pre-generated rules.json works correctly for seed 1. Regenerating rules produces different output that fails tests. **Do not regenerate rules.json for SC2**.

## Current Status
- Seed 1: ✅ PASS with pre-generated rules.json
- Regeneration: ❌ FAILS - produces different rule structures

## Critical Finding: Original rules.json Uses Mixed Approach

### The Original rules.json
The working pre-generated rules.json uses a **mixed approach**:
1. **Some helpers are kept as simple calls** (e.g., `terran_competent_comp` for Shatter the Sky locations)
2. **Other helpers are expanded to full rule logic** (e.g., `terran_early_tech` expanded to Or/And/HasAny rules)

### Example - Same Location, Different Approaches

**Helper kept as simple call (for Shatter the Sky):**
```json
{
  "rule": "terran_competent_comp",
  "_original_ast_type": "helper",
  "_converted_from_cc": true
}
```

**Helper expanded to full logic (for other locations):**
```json
{
  "rule": "Or",
  "children": [
    {"rule": "And", "children": [...]},
    {"rule": "HasAny", "args": {"items": [...]}}
  ]
}
```

### Root Cause
The original rules.json was generated by a specific exporter configuration that:
1. Expanded certain helpers to their full logic (captured at generation time)
2. Kept certain helpers as simple references (for frontend evaluation)
3. The exact configuration/version that produced this output is unknown

The current exporter produces different output because:
1. The blacklist controls which helpers become `True_`
2. The rule analyzer parses helper source code differently
3. There's no mechanism to reproduce the original mixed approach

### Attempts Made

1. **Adding KNOWN_SC2_HELPERS set** - Keeps all listed helpers as simple calls
   - Result: All helpers become simple calls (no expansion)
   - Causes: Different rule structure than original

2. **Reducing HELPERS_TO_EXPORT_BLACKLIST** - Let more helpers be exported
   - Result: Fewer True_ entries but still different structure
   - Causes: Test mismatches

### Why Simple Regeneration Fails
When regenerating, the exporter either:
1. Expands helpers to `AST_block` format (complex, frontend can't evaluate)
2. Converts to `True_` (if blacklisted)
3. Converts to simple helper calls (missing the expanded logic)

None of these match the original's mixed approach where some helpers are expanded and others are kept as calls.

## Workaround
**Do not regenerate rules.json for SC2.** Use the pre-generated version which was created by a specific exporter configuration.

## Future Fix Required
To properly regenerate SC2 rules, the exporter needs:
1. A mechanism to selectively expand some helpers while keeping others as calls
2. Understanding of which helpers should be expanded vs kept as calls
3. Possibly a "known good" reference to compare against
